# Project index

This index routes external readers and the portfolio LLM to one public-safe page per project family. It combines the active portfolio audit with projects listed on the homepage; related public/private repositories are described together when they form one coherent system.

## Apps and products

- [Overtone.art](projects/overtone.md) — an end-to-end photography gallery and print storefront spanning web, mobile, backend, payments, fulfillment, media processing, and AI-assisted catalog content, including the Mood design-discovery surface built on the same platform.
- [WallSnap](projects/wallsnap.md) — reusable geometry and rendering infrastructure plus a hosted Shopify experience for previewing artwork at scale inside room photography.
- [AngleForge](projects/angleforge.md) — an ad-creative production system that turns an offer into claim-checked angle, hook, style, and placement variants with deterministic rendering.
- [Countersign](projects/countersign.md) — open-source and hosted human-approval primitives for pausing consequential LangGraph actions and resuming them with structured reviewer decisions.
- [Timerail](projects/timerail.md) — a headless-first React calendar and resource scheduler with accessible interaction models, themeable UI layers, and dense planning views.
- [Gallery SaaS](projects/gallery-saas.md) — a multi-tenant photography commerce platform with storefront, account, operator, marketing, payment, and print-fulfillment systems.
- [Agent Signals](projects/agent-signals.md) — a small signal broker, MCP surface, hooks, and native notification client for long-running AI-agent workflows.
- [Spendgate](projects/spendgate.md) — graph-level token and cost governance for LangGraph, including hierarchical budgets and checkpoint-aware interruption.
- [Homepage](projects/homepage.md) — the portfolio itself: a Next.js experience with a physics-driven visual identity, structured resume data, SEO metadata, and a grounded LLM chat.

## Developer tools and internal systems

- [mcpmake](projects/mcpmake.md) — a CLI, generation library, and hosted system that converts API descriptions and captures into editable Model Context Protocol servers.
- [Frontend Debugger](projects/frontend-debugger.md) — an MCP and desktop toolkit that lets coding agents inspect framework component state, accessibility, visual changes, and browser sessions.
- [btw](projects/btw.md) — a context-aware personal knowledge agent available as a terminal UI, desktop application, MCP/ACP server, browser extension, and Telegram bot.
- [canvas-editor](projects/canvas-editor.md) — a framework-neutral Fabric.js editing engine with React bindings, format conversion, templates, shapes, cloud adapters, and image-processing extensions.
- [Skills](projects/skills.md) — reusable coding-agent skills, templates, validation scripts, and documentation for repeatable engineering workflows.

## Libraries

- [printify-sdk](projects/printify-sdk.md) — a typed TypeScript client for Printify's API.
- [prodigi-print-api](projects/prodigi-print-api.md) — a typed TypeScript client for Prodigi's Print API with an interactive React explorer.
- [Store AI](projects/store-ai.md) — framework- and state-store-neutral adapters for consuming AI streams across fourteen frontend ecosystems.
- [stream-schema](projects/stream-schema.md) — a small streaming structured-data layer with core, React, Vue, and Zod integrations.
- [zustand-sagas](projects/zustand-sagas.md) — Redux-Saga-style generator orchestration adapted to Zustand stores.
- [vue-sagas](projects/vue-sagas.md) — an experimental saga runtime with framework-neutral, Vue, and Pinia packages.
- [ripple-text](projects/ripple-text.md) — a physics-driven text-animation engine for pointer and touch ripple effects.

## Learning systems

- [learn-ai](projects/learn-ai.md) — a TypeScript and Python curriculum spanning LLM fundamentals, RAG, agents, multimodality, evaluation, security, operations, and from-scratch implementations.
- [learn-fullstack](projects/learn-fullstack.md) — a large TypeScript curriculum from language and browser fundamentals through production React, backend, data, realtime, testing, and deployment systems.

## Interpretation notes

“Internal” means the project was built to support other work; it does not imply weaker engineering. “Experiment” means it was used to explore a technical idea and should not be represented as a currently operated product. The absence of commercial or user metrics is deliberate: this wiki documents engineering experience, not confidential business performance.
